five moves.

You do not freeze because you lack Python. You freeze because a blank editor gives you no order to work in. So here is the order. It never changes — not for a list, not for a dict, not in an interview. Learn the five moves and the blank page stops being blank.

§01 — the frame

Door, box, walk, work, hand back.

Notice what is not on that list: cleverness. Moves 1, 2, 3 and 5 are almost identical in every problem you will ever be given. Only move 4 — the work — actually changes. That is the whole trick: four of the five are free.

§02 — watch it happen

One problem, five presses.

The problem. Given a list of prices, give back the total. total_price([3, 5, 2]) should come back as 10.
0 / 5
Q · the interviewer asks

"Talk me through how you'd approach this before you write anything."

Say the moves out loud: "One parameter, the list. I need a running total starting at zero, before the loop. Loop over each price, add it on. Return the total after the loop finishes — not inside it." That sentence, said before typing, is most of what they are scoring.

§03 — your turn

Build three, line by line.

Same five moves, three different shapes of answer — a number, a list, a table. Pick each line. Wrong picks are not punished, they are explained: you find out exactly what Python would have done. At the end the finished function runs for real, in this page.

§04 — the one that gets everyone

Four spaces or eight?

This is the bug you have written four times already. The code is identical except for the indent of one line — and the indent is what decides whether return belongs to the loop or to the function. Run both. Real Python, right here.

not run yet

return inside the loop — 8 spaces

def total_price(prices): total = 0 for p in prices: total += p return total print(total_price([3, 5, 2]))
—

return after the loop — 4 spaces

def total_price(prices): total = 0 for p in prices: total += p return total print(total_price([3, 5, 2]))
—
Both are valid Python. Both run. Only one is right — and nothing will warn you.
Q · the interviewer asks

"Your function returns 3 instead of 10. Where's the bug?"

The answer they want in one line: "return is inside the loop, so it exits on the first item." return does not mean "remember this" — it means stop the function now and hand this back. If it sits at the same indent as the body of the loop, it fires on iteration one and the other items are never seen.

§05 — the first decision

Name the box.

Move 2 is the move that decides everything after it. Get the box right and the rest of the function almost writes itself; get it wrong and you fight the code for ten minutes. Read the problem, pick the box. Eight of them.

§06 — carry this

The card that goes in your head.

# 1. door — what comes in?def name(data): # 2. box — where does the answer collect? out = 0 # or [] or {} or set() or "" # 3. walk — visit each one for x in data: # 4. work — what happens to ONE item? out += x # 5. back — after the loop, four spaces return out

Write that skeleton first. Every time. Before you have any idea how to solve the problem, you can already type moves 1, 2, 3 and 5 — because they only depend on what goes in and what comes out, which the question already told you. Then you sit and think about move 4 with four fifths of the function already on screen. That is the difference between staring at a blank editor and staring at one small gap.

Q · the interviewer asks

"You've gone quiet. What are you thinking?"

Never go quiet. Type the skeleton and narrate it: "I'm setting up the shape first — takes a list, returns a count, so I need a counter before the loop and a return after it. Now let me think about the condition." You have said something true and useful while buying yourself thinking time.
