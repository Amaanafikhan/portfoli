01 Before any of it

Which loop, and what the variable holds

Almost every "I got confused assigning values" moment comes from here. Four loop forms, the same list, and what the loop variable actually contains in each. Click through them.

The decision, in one line each

for x in arr — you only need the values, front to back. Cannot assign back into the list.
for i in range(len(arr)) — you need the position, because you're writing into the list or comparing neighbours.
while cond — the pointers move at different speeds, or move conditionally. You control every step.
while left < right — two pointers converging from the ends.

What goes wrong with while

A for loop advances itself. A while loop does not — you must move the variable, and every path through the body must move it. Forget it inside one if branch and the program hangs forever with no error message, no traceback, nothing. Before you run any while, point at the line that changes the condition. If you can't find it, it isn't there.

Never mutate what you're looping over

Removing items from a list while iterating it makes the loop skip elements — the indexes shift underneath you and nothing warns you. Build a new list, or loop over a copy with for x in items[:], or walk backwards with range(len(items) - 1, -1, -1).

02 The confusion, named

Which side of the = you're on

One rule, and it never has an exception

arr[i] on the left of = writes into the slot.
arr[i] on the right of = reads out of the slot.

So nums[write] = nums[read] means: take the value at read, put it at write. Left is the destination, right is the source — the same way as everywhere else in the language. When you're unsure which pointer goes where, ask "what am I copying, and where is it going?" and the answer places both.

Swapping, and why Python needs no temp

a, b = b, a — Python builds the entire right side first, as a tuple, then unpacks it into the left. The old values are safely captured before anything is overwritten. That's why arr[i], arr[j] = arr[j], arr[i] works, and why the same thing written as two separate lines destroys a value.

Two more that bite

i += 1 moves the pointer. arr[i] += 1 changes the data. They look alike and do entirely different things.

arr = other rebinds your local name and leaves the caller's list untouched. arr[:] = other overwrites the contents in place, which the caller does see. If a question says "in place," the difference is the whole grade.

05 Before you write a line

The seven questions

Run this list every time. It takes twenty seconds and it prevents most of the wrong turns.

  1. What technique is this? Name it out loud before touching the keyboard. If nothing fits, you're missing something in the question.
  2. Do I need the index, or just the value? This picks your loop form and nothing else does.
  3. Am I allowed extra space? "In place" or "O(1) space" rules out the hash map and forces pointers or maths.
  4. Is the input sorted? If yes, two pointers or binary search are probably intended. If not, is sorting it first allowed?
  5. What moves the loop forward? Point at that exact line. For a while, check every branch reaches it.
  6. What are my edge cases? Empty input, one element, all identical, all negative. Say them before you code.
  7. Walk it on paper with three items. Every off-by-one you'll ever have shows up in the first three steps.
