00 before you write another line

Reading code is a
separate skill.
Nobody teaches it.

You have been trying to write code you cannot yet read. That is backwards, and it is why the keyword lists feel like noise. So: first why each keyword exists — the pain it removes, which is the only thing that makes a name stick. Then how to look at a block of code and know what you are looking at.

02 the one rule

Indentation is ownership

There is exactly one rule for reading Python's shape, and it has no exceptions:

Every line belongs to the nearest line above it that is less indented.

A : at the end of a line means "a body follows, indented underneath". That's it. That single rule explains classes, functions, loops, ifs — all of them.

Tap any line. It shows you who owns that line, and which lines it owns.

03 the method

Read by levels, not by lines

Never read code top to bottom on the first pass — that is how it turns into soup. Read one indent level at a time, and stop as soon as you understand enough. Most of the time you never need level 3 at all.

04 the game

Which lines actually run?

The one thing that confuses everyone about a file full of def: defining is not running. Tap the lines whose body actually does work, in the order it happens. Wrong taps explain themselves. Three rounds.

06 carry this

What to do when code looks like a wall

  1. Read only the left edge first. Ignore everything indented. Those few lines are the table of contents.
  2. Go in one level. Read the def names only, not their bodies. Now you know what the thing can do.
  3. Pick one body — the one you actually care about — and only then read inside it.
  4. For any confusing line, find its owner. Look straight up for the first line that starts further left. That line owns it.
  5. Ask "does this run, or is it being filed?" A def line files a recipe. Only a call cooks it.
  6. Find the bottom. The lines at the left edge near the end are usually what actually starts everything.
  7. Say the shape out loud before any detail: "It's one class, with three methods, and the last two lines use it." If you can say that, you can read it.
