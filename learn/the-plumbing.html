00 Read this first

There are two different worlds

Half your confusion is that these get taught mixed together. They are not the same, and knowing which one you're in tells you exactly what to write.

Interview & real code

def two_sum(nums, target):
    ...
    return [i, j]

Values arrive as parameters, already the right type. You hand the answer back with return. Nobody types anything. There is no input() anywhere.

Practice sites & exercises

n = int(input())
nums = list(map(int, input().split()))
print(solve(nums))

You read from the keyboard, and everything arrives as a string, so you convert. You show the answer with print. This layer wraps the function — it isn't the function.

The habit that keeps them separate

Write the function first — parameters in, return out, no printing. Then add the reading and printing underneath as a separate few lines. Now the same function works in an interview, in a test, and on a practice site, and you never have to rewrite it.

01 Taking data in

Every way values reach your code

Six ways, in the order you'll need them. The first two cover almost everything you'll actually write; the rest are for practice sites and files.

The one that catches everyone

input() always returns a string. Always. Type 5 and you get "5", and "5" + 1 is a TypeError. Nothing warns you — the program just breaks somewhere later. If a number came from input(), it needs int() around it.

Where the values actually live

A parameter is just a name that gets pointed at whatever the caller passed. def f(nums) then f(scores) means inside the function, nums and scores are two names for the same list — so if you mutate it inside, the caller sees the change. That's the same "names are labels" rule from the Day One page, and it's why "in place" questions work at all.

02 Converting

Turning what you got into what you need

This is the join between taking data in and using it. Nearly every "why doesn't this work" on a practice site is a missing conversion.

join only accepts strings

" ".join([3, 1, 4]) raises TypeError: sequence item 0: expected str instance, int found. You must convert first — that's why the last row above has str(x) in it. Or skip join entirely and use print(*nums), which does the same thing for output.

03 Giving it back

return versus print

If one thing on this page fixes your confusion, it's this. Both functions below look like they work. Press the button and watch what result actually holds afterwards.

✗ prints the answer
def double(n):
    print(n * 2)

result = double(5)
print("result is", result)
✓ returns the answer
def double(n):
    return n * 2

result = double(5)
print("result is", result)

Why the left one is useless

print shows a value on screen and hands back nothing. So result is None — you cannot add it, store it, sort it, or return it from the function that called it. On screen both look identical, which is exactly why this bug survives so long. A test harness calls your function and checks what came back; it never looks at the screen.

The rule

Functions return. Only the outermost layer prints. If you want to see a returned value, wrap the call: print(double(5)).

04 Going through it

Pick your loop by what you're holding

You never have to guess. Two questions — what shape is my data, and do I need the position — pick the loop for you every time. Click a shape.

What you have and needThe loop
List — just the valuesfor x in arr
List — position and valuefor i, x in enumerate(arr)
List — writing back into itfor i in range(len(arr))
String — each characterfor ch in s
Dict — the keysfor k in d
Dict — keys and valuesfor k, v in d.items()
Two lists, side by sidefor a, b in zip(xs, ys)
Grid / list of listsfor row in grid: for cell in row
Backwardsfor x in reversed(arr)
Pointers moving unevenlywhile cond

Three things that will bite while looping

Never delete from a list you're looping over — the indexes shift under you and items get silently skipped. Build a new list instead.

zip stops at the shorter list. No error, no warning — the extra items are simply ignored.

sorted(arr) returns a new list; arr.sort() returns None and reorders in place. Writing arr = arr.sort() destroys your list.

05 The template

Type this from memory until it's automatic

This shape works for every practice problem you'll meet. The function is the part an interviewer wants; the bottom half is the part that lets you run it.

# ---- the function: values in, answer out. No printing. ---- def solve(nums, target): for i, n in enumerate(nums): if n == target: return i # leaves the function immediately return -1 # the "not found" case — never forget this # ---- your own tests: run the file and read the output ---- if __name__ == "__main__": print(solve([4, 9, 2], 9)) # expect 1 print(solve([], 9)) # expect -1 (empty) print(solve([9], 9)) # expect 0 (one item) # ---- only if a practice site feeds you keyboard input ---- # n = int(input()) # nums = [int(x) for x in input().split()] # print(solve(nums, n))

Why the three test calls matter more than they look

Normal case, empty input, single item. Those three catch most off-by-one and crash bugs before anyone else sees them — and running them takes four seconds. Never trust code you haven't run.

06 Keep these

Seven rules that cover the plumbing

  1. Functions return. Only the outer layer prints. A function that prints its answer hands back None.
  2. input() is always a string. Wrap it in int() the moment you need a number.
  3. [int(x) for x in input().split()] — the one line that reads a row of numbers. Know it cold.
  4. join needs strings, so convert first, or use print(*nums) instead.
  5. Need the position? enumerate. Need to write back into the list? range(len(arr)). Otherwise just for x in arr.
  6. Never mutate a list you're looping over, and remember .sort() returns None.
  7. Every path must return something. Falling off the end of a function gives None, and that None will crash somewhere far away from the real cause.

Now the patterns will land

With the plumbing solid, "the values arrive as nums, you return an answer" stops being a question — and every trace on the techniques page gets easier to follow.
