02 — Same trap, new file

Django's urls.py has FizzBuzz's exact bug

Django checks your URL patterns top to bottom and stops at the first match — identical to if/elif. Drag these three patterns into an order, then send a request to /tasks/new/ and see which one catches it.

Arrange the three patterns, then send the request. Watch which one intercepts /tasks/new/.

The accurate rule: a pattern only shadows a later one if it can actually match. tasks/<int:id>/ is harmless above tasks/new/, because int only accepts digits. The real danger is a catch-all like tasks/<str:slug>/, which matches anything — always put specific paths above it.
